# M11 长期记忆（对话摘要 + 用户画像双轨）

> 2026-09-07 立项。目标：把「内存 sessions（重启即失）」升级为「跨会话持久记忆」，越用越懂。
> 用户原话选型依据：7 项进阶能力核查中 #5「长期记忆」判定为全清单最大空白，选中补齐。

## 1. 现状与差距

- 现状：`server.py` 内存 `dict sid→history`，TTL 30min / 保留 6 轮，**重启即失**；无落盘、无摘要压缩、无画像。
- 差距：跨会话（重启 / 换 sid）后系统对用户毫无记忆，同一偏好问题每次都要从头检索问一遍。

## 2. 设计原则

1. **采集与加工分离**（与 M1-M6 断点续传同风格，不拖慢回答流）：
   - **在线零成本采集**：Web 每轮问答把 `(session, role, content)` 原样追加 `dialog_log` 表——纯本地 sqlite，无 LLM 调用。
   - **离线 digest 加工**：LLM 把未处理轮次压成「对话摘要」+ 抽「用户画像」，失败静默跳过，不影响服务。
2. **记忆是背景不是事实来源**：注入只用于个性化措辞与理解上下文，回答的事实依据仍是检索片段（防幻觉：避免拿「上次聊过的结论」当本轮新事实）。
3. **本地优先**：全部落 `data/xhs.db` 三张新表，可 `cli memory clear` 一键清空（个人数据可控）。

## 3. 数据模型（schema.sql 追加）

| 表 | 作用 | 关键字段 |
|---|---|---|
| `dialog_log` | 对话原文流水（采集） | id / ts / session / role / content / digested |
| `memory_digests` | 对话摘要轨（跨会话背景） | id / summary / span(轮次) / created_at |
| `profile_entries` | 用户画像轨 | id / content / source(证据) / hit_count / first_seen / last_seen / active |

## 4. digest 流程（`src/xhs_rag/memory.py`）

```
dialog_log 未 digest 行 → 规则分块（同 session 连续 + 时间 gap>10min 断块 + 每块≤8轮）
  每块 ──① 摘要轨──> LLM 压成 1-2 句 summary → memory_digests
       ──② 画像轨──> 仅 user 消息 → LLM 抽稳定画像 → upsert_profile（规则去重）→ profile_entries
全部 id → mark_digested
```

- **分块规则**：按 `(session, 相邻时间 gap)` 切块，不依赖 LLM 判断，行为可预期。
- **画像去重（规则，非 LLM）**：归一化后与 active 画像比对——完全相同 → `hit_count+1`；新文本是旧文本超集 → 保留新、忽略旧；否则插入。避免 LLM 合并带来的级联丢失（升级位：画像量 >100 后可换 LLM 合并）。
- **结构化输出三级降级**：`json.loads` → 正则抓 `{...}` → ast 兜底（照搬 RAGAS LLM-judge 三坑经验）。
- **分块摘要注入**：回答前查 `memory_digests` 最近 2 条 + `profile_entries` 高频 6 条 → 拼成「背景注记」插到 system 之后。

## 5. 触发时机

| 入口 | 动作 |
|---|---|
| Web `/api/answer` 每轮完成 | 写 `dialog_log`（同步，ms 级） |
| `serve` 启动 | 后台线程跑一次 `run_digest`（不阻塞 UI 启动） |
| `cli memory digest` | 手动触发（M7 调度可定时调） |
| `cli memory show / clear` | 查看 / 清空 |

## 6. 验收

1. 造多轮含画像内容的对话日志 → `cli memory digest` → `memory_digests` 有摘要、`profile_entries` 抽出正确画像。
2. 重复 digest 幂等：已消费轮次不再重复加工；重复画像只累计 hit 不重复插入。
3. `/api/answer` 生成的 prompt 带背景注记，且回答事实仍只依据检索片段。
4. LLM 不可用时 digest 报错不影响 serve / 问答主流程。
